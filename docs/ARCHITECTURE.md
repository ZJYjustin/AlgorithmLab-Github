# 实现原理

## 数据流

```text
CLI / IDE 可视化入口
        ↓
lab.py：选择运行方式并管理子进程
        ↓
Python 追踪 / Python 状态快照 / C、C++ 命令记录
        ↓
统一帧数据：line + panels 或 variables
        ↓
viewer.html + JSON → 独立 HTML 报告
        ↓
浏览器按帧回放
```

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `lab.py` | 解析参数、选择编译器和解释器、启动子进程、限制时间、生成报告 |
| `worker.py` | 执行 Python 文件，收集普通逐行记录或动画快照 |
| `algorithm_lab.py` | 数组、矩阵、日志面板及 `step()` 快照接口 |
| `include/algorithm_lab_c.h` | 将 C/C++ 的显式记录调用写为 JSON 命令 |
| `protocol.py` | 将命令序列转换为面板状态和播放帧 |
| `viewer.html` | 显示源码、变量和面板，提供播放与单步控件 |
| `plugins/` | IDE 菜单、编辑器工具条、解释器设置和运行器调用 |
| `package_vsix.py` | 使用微软构建工具生成并检查 VSIX 元数据和负载路径 |

## 普通 Python 的逐行记录

`worker.py` 使用 `sys.settrace` 订阅目标文件的行、返回和异常事件。
行事件发生在对应语句执行之前。工作进程对局部变量进行有限深度和数量的序列化，避免直接调用任意对象的 `repr()`。
追踪最多保留 4000 帧，不跟踪其他线程或依赖库内部的执行过程。

## 显式 Python 动画

`ArrayView`、`MatrixView` 和 `Journal` 保存面板状态。
`step()` 深复制全部面板，并从调用栈获取行号。复制保证后续状态更新不会修改历史帧。
Python 执行结束后，工作进程导出快照；自动模式优先使用这些动画帧。

## C/C++ 命令记录

运行器为编译步骤添加头文件目录，将当前源文件编译为临时程序，再运行该程序。
环境变量 `ALGORITHM_LAB_TRACE` 指定记录文件。头文件输出包含 `key`、`method`、`args` 的 JSON 命令；程序退出时关闭记录。
`protocol.py` 按顺序应用设置、选中和日志命令，遇到 `delay` 命令时保存一帧。

## HTML 回放

运行器把 JSON 帧数据嵌入 `viewer.html` 模板，生成可离线打开的单个文件。
嵌入数据中的小于号等字符经过转义；播放器通过文本节点显示源码和日志。
播放器维护当前帧序号，播放时递增，后退时递减，不重新执行用户程序。

## IDE 启动入口

PyCharm 入口使用 Java 实现，Visual Studio 编辑器工具条使用 C# 实现。
两者寻找打包在插件内的 Python 运行器，用选定的解释器启动 `lab.py`，并传入当前已保存文件的路径。
IDE 负责提供启动入口，浏览器负责展示报告。插件的启用状态与算法程序的执行状态相互独立。

## 修改入口

- 新增算法：在 `examples/` 中编写算法并添加记录调用。
- 改变布局或播放控件：修改 `viewer.html`。
- 扩展命令：同时修改 C/C++ 记录头文件与 `protocol.py`，并添加行为测试。
- 改变 Python 变量显示：修改 `worker.py` 的序列化逻辑。
- 修改 IDE 入口：编辑 `plugins/` 中对应平台的源文件并重新构建。
